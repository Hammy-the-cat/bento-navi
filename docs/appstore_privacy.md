# App Store プライバシー申告 手順書

App Store Connect の「App のプライバシー」に何をどう入力するかをまとめたもの。
**この内容は v1.0（アプリ版に広告なし）の構成に対応している。**
アプリ版に広告を入れる場合は、必ず §4 を読んでから申告をやり直すこと。

---

## 1. 結論：申告する内容

| 質問 | 回答 |
|---|---|
| このAppからデータを収集していますか？ | **はい** |
| データタイプ | **位置情報 → 正確な位置情報** のみ |
| 使用目的 | **Appの機能** のみ |
| このデータはユーザーのIDにリンクされていますか？ | **いいえ** |
| このデータはトラッキングに使用されますか？ | **いいえ** |

上記以外のデータタイプ（連絡先情報・識別子・使用状況データ・診断など）は**すべて該当なし**。
チェックを入れるのは「正確な位置情報」の1つだけ。

---

## 2. App Store Connect での操作手順

> ⚠️ `appstoreconnect.apple.com` はユーザー自身が操作する必要がある。

1. App Store Connect → **マイApp** → **べんとうナビ** を開く
2. 左サイドバーの **「App のプライバシー」** をクリック
3. 「データ収集」の右にある **「編集」** をクリック
4. **「はい、このAppからデータを収集しています」** を選んで「次へ」
5. データタイプの一覧が出るので、**「位置情報」グループの中の「正確な位置情報」だけ**にチェックを入れて「保存」
   - 「おおよその位置情報」にはチェックを**入れない**
6. 一覧に戻ると「正確な位置情報」の行が追加されているので、その行の **「設定」** をクリック
7. **使用目的**：**「Appの機能」だけ**にチェック
   - 「サードパーティ広告」「デベロッパの広告またはマーケティング」「アナリティクス」「製品のパーソナライズ」「その他の目的」は**すべてチェックしない**
8. **「このデータはユーザーのIDにリンクされていますか？」** → **「いいえ、このAppから収集された位置情報はユーザーのIDにリンクされていません」**
9. **「このデータはユーザーのトラッキングに使用されますか？」** → **「いいえ」**
10. 「保存」→ 画面右上の **「公開」**

## 3. なぜこの内容になるのか（根拠）

### 3-1. なぜ位置情報だけなのか

v1.0 のアプリが端末の外に送るのは、**店舗検索のための座標と検索語だけ**。

外部通信先（`lib/services/bento_service.dart`）:

| 宛先 | 用途 |
|---|---|
| `nominatim.openstreetmap.org` | 会場名 → 座標の変換 |
| `overpass-api.de` / `overpass.kumi.systems` / `maps.mail.ru` | 周辺店舗の検索 |
| `tile.openstreetmap.org` | 地図タイルの表示 |
| `google.com/maps/dir/` | 経路案内（ユーザーがリンクを開いたときだけ） |

解析ツール（Firebase / Sentry / Analytics 等）は**一切入っていない**。広告SDKも v1.0 では入っていない。

### 3-2. 「正確な位置情報」を選ぶ理由

コードでは `LocationAccuracy.medium` で取得しているが（`home_screen.dart:236`）、
検索APIに渡しているのは**緯度経度そのもの**。Apple の定義では

> 小数点以下3桁以上の緯度経度と同等以上の解像度 = 正確な位置情報

なので「正確な位置情報」に該当する。

### 3-3. 検索履歴を申告しない理由

検索履歴は `shared_preferences` で**端末内にのみ**保存され、外部に送信されない。
Apple の「収集」の定義は

> リアルタイムのリクエストを処理するために必要な期間を超えて、開発者や第三者パートナーがアクセスできる形で端末外にデータを送信すること

端末から出ないデータは「収集」に当たらないため、申告不要。

### 3-4. 位置情報は厳密には申告不要とも読めるが、申告する

座標を Overpass に送るのは「その場の検索リクエストを処理するため」だけで、
自分のサーバーには一切保存していない。上記の定義を厳密に当てはめると
「収集していない」とも解釈できる。

ただし**位置情報はユーザーが最も気にする項目**であり、過少申告はリジェクトの原因になる一方、
過剰申告でリジェクトされることはない。**安全側に倒して申告する。**

### 3-5. トラッキングが「いいえ」の理由

Apple のトラッキングの定義は

> 自分のAppで収集したユーザー／端末データを、**他社**のApp・Webサイト・オフラインの情報と結合して、
> ターゲティング広告または広告効果測定を行うこと。データブローカーへのデータ共有も含む。

v1.0 にはこれに該当する仕組みが一切ない（広告SDKなし・解析なし・第三者への識別子送信なし）。
したがって **ATT（App Tracking Transparency）のダイアログを出す必要もない**。
`Info.plist` に `NSUserTrackingUsageDescription` を追加してはいけない（不要なダイアログが出るだけ）。

## 4. 【重要】アプリ版に広告を入れるときにやり直すこと

### 4-1. v1.0 で広告を外した経緯

もともと `google_mobile_ads`（AdMob）が入っていたが、v1.0 提出前に**丸ごと削除**した。理由は3つ。

1. **実ユーザーに Google の「Test Ad」バナーが表示される状態だった。**
   `ad_banner.dart` はテストIDかどうかを見ずに常にAdMobバナーを表示していたため、
   そのまま公開すると購入者にテスト広告が出続ける（審査ガイドライン 2.2 の指摘リスク）
2. **AdMob にアプリを登録しておらず、実IDが存在しないため収益はゼロだった。**
   つまり載せていても得るものがなかった
3. **広告SDKがあるとプライバシー申告が一気に複雑になる**（次項）

削除したコミット: `git log --oneline --grep="アプリ版の広告"` で見つかる。
戻すときはこのコミットを `git revert` すればよい。

### 4-2. 広告を戻すときの前提条件

- **AdMob でアプリと広告ユニットを登録し、実IDに差し替えること。**
  テストIDのまま公開してはいけない
- 差し替える箇所は3つ:
  `lib/config/ad_config.dart` / `ios/Runner/Info.plist` の `GADApplicationIdentifier` /
  `android/app/src/main/AndroidManifest.xml` の `com.google.android.gms.ads.APPLICATION_ID`
- ⚠️ **自分で実広告をタップすると規約違反（アカウント停止）**。動作確認はテストIDのままで行う

### 4-3. 広告を入れた場合に追加で申告が必要になるデータタイプ

Google Mobile Ads SDK が収集するもの（Google 公式のデータ開示より）。
§1 の表を捨てて、以下を**追加で**申告し直すことになる。

| データタイプ | 使用目的 | IDにリンク |
|---|---|---|
| 識別子 → デバイスID | サードパーティ広告、アナリティクス | はい |
| 使用状況データ → 広告データ、製品の操作 | サードパーティ広告、アナリティクス | 要確認 |
| 診断 → クラッシュデータ、パフォーマンスデータ | アナリティクス、Appの機能 | パフォーマンスのみ「はい」 |
| 位置情報 → おおよその位置情報 | サードパーティ広告（IPアドレスからの推定） | 要確認 |

**トラッキングの扱い**は、どちらの方針を取るかで変わる。

- **方針A（推奨・シンプル）**: ATT を実装しない → トラッキング「いいえ」
  - この場合、`AdRequest(nonPersonalizedAds: true)` を明示して**非パーソナライズ広告に固定する**こと
  - （プラグイン 9.0.0 にこのパラメータが存在することは確認済み）
  - iOS では ATT なしだと IDFA が取れないため、実質的にどのみち非パーソナライズになる
- **方針B**: ATT を実装して許可を求める → トラッキング「はい」
  - `NSUserTrackingUsageDescription` の追加とダイアログ実装が必要
  - 許可率は低いので、手間の割に見返りは小さい

### 4-4. プライバシーポリシー（`web/privacy.html`）は変更不要

公開中のプライバシーポリシーは**すでにアプリ版の AdMob を織り込んだ内容**になっている
（3章が「Web版=AdSense / アプリ版=AdMob」の2本立て）。
広告を戻したときにポリシー側の修正は要らない。

> 逆に v1.0 の時点では、ポリシーが実装より広めに書かれている状態。
> ポリシーは「利用する場合があります」という書き方なので、これは問題ない。
