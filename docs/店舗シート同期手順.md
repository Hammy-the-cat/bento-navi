## 更新手順

1. Google Driveで新しい地域シートの有無を検索する。各ファイルのメタデータとタブ一覧を取得し、登録済みタブの欠落や新タブを確認する。
2. 店舗タブの必要な全列を、メタデータの最終行までGoogle Sheetsコネクタで読む。電話番号は表示形式で取得。ヘッダー16列（宮崎・鹿児島は18列）を省略しない。非店舗タブは取り込まない。
3. 下記形式のJSONをローカル保存する。シートの権限を一般公開に変える必要はない。今回の完全取得データは `../tmp/bento-sheet-audit-20260920/sheets.json` に保管。
4. `node tool/sync_sheet_snapshot.mjs <snapshot.json>` で検証。問題がなければ `--write` を付けて再実行。`--allow-removals` はシートから消えたIDを確認してから使う。新しい地域・タブはレジストリへ明示登録する。
5. `node --test tool/sync_sheet_snapshot.test.mjs`、`python tool/check_shop_catalog.py`、`flutter analyze`、`flutter test`、`flutter build web --release --base-href /` を実行する。
6. gh-pagesの最新内容を基に、ビルド済みFlutterファイルを配置して公開する。CNAME、公開記事、最新privacy.htmlを保持。公開先 `https://bento.hammythecat.com/` の店舗JSONのSHA-256と件数が監査結果と一致することを確認する。
7. iOSはデータを同梱しているため、新しいビルドをTestFlightで確認してApp Storeへ更新する必要がある。Web公開だけで既存のiOSアプリは更新されない。審査中の1.3.0を取り下げる必要はなく、次版として進める。

## 反映漏れを防ぐ仕組み

- `assets/shops.json` が地図検索と地域別一覧の共通データ。緯度経度なしの店舗も削除せず、地域別一覧に掲載する。座標を推測して地図に置かない。
- 既存の169件の補完済み座標は、住所が同じ場合のみ保持。住所変更後に古い座標を流用しない。不正・片側だけの座標は同期を失敗させる。
- `docs/data/sheet-sync-audit.json` に全店舗ID、元シート・行番号、閉店除外、座標未取得、データのハッシュ値を記録する。
- タブの欠落、読み取り範囲不足、必須列不足、ID重複、未確認の削除は書き込み前に停止する。
- Codemagicでも監査とアプリデータの一致を検証する。旧CSV・JSON取込ツールだけで書き換えた状態はビルドを通さない。

現状は「更新時に同期して検証・公開する」運用。シート編集を自動監視して配信する仕組みではない。今後の更新依頼でも、この手順で元シートから公開先まで照合する。
