# スプレッドシートから店舗情報を自動更新

## 構成と対象

- 登録元: `tool/sheet_sources.json` の12冊・38店舗タブ。関東・熊本・沖縄のシートは未登録。
- GitHub Actions: `.github/workflows/sheet-catalog.yml`、毎日04:41 JST。開始はGitHub側の混雑で遅れる場合がある。
- Googleの既存読み取り可能なエクスポートを利用。共有設定変更なし、シート書き込みなし。
- ローカルPCの常時起動は不要。XLSX解析はActions上、配信は加工済み店舗情報のみ。
- GitHub変数 `SHEET_CATALOG_PUBLISH=true` で有効。停止時は `false` にする。
- 既存のバケット限定R2キー `SHOP_DATA_R2_ACCESS_KEY_ID` / `SHOP_DATA_R2_SECRET_ACCESS_KEY` を再利用する。
- OSMの週次更新とは別ジョブ・別ポインタ。片方の取得失敗で他方のデータを上書きしない。
- 新しい冊子・タブの追加はレジストリを更新して初回検証する。Drive全体の自動探索は行わない。

## 検証と配信

1. R2から前回の正常データを取得。初回だけ同梱の `assets/shops.json` を基準にする。
2. 登録済み12冊を最大2並列で完全取得する。既知の調査メモ・裏付け一覧などは対象外。
3. 既存の行単位照合に加え、重複、住所変更後の古い座標、地域別の件数急減を検証する。
4. JSONをgzip圧縮。内容が同じならバージョンは同じで、R2への公開を省略する。
5. `catalog/versions/<内容SHA-256>.json.gz` を保存し、全体を読み戻して照合する。
6. `catalog/active.json` を条件付き書き込みで最後に切り替える。直前版の情報は `previous` に残す。
7. 公開APIから取得し、ハッシュ・件数・ID重複・閉店除外を検証する。

公開API:

- `https://bento-navi-overpass-proxy.excitedcherry0909.workers.dev/catalog/manifest.json`
- manifest内の `path` が圧縮済み店舗一覧のURLパス。

初回データ: 11,022件、地図に置ける店舗11,015件、一覧のみ7件。同梱データと全項目一致。JSON約7.15MBを723,193バイトへ圧縮。件数はシート記載との照合であり、営業を全店舗再調査したものではない。

## アプリの動作

- 1.3.2以降で対応。既存iOS利用者は対応版へのアプリ更新が一度必要。
- 検索時は端末内データを即利用し、更新通信を待たない。
- 起動・復帰・検索・地域別一覧の利用で裏側の確認を開始。正常時は6時間、失敗時は5分空ける。同時取得を重複させない。
- バージョンが同じなら小さなmanifestだけを取得。変更時のみ圧縮データを取得する。
- SHA-256・件数・全店舗の項目・座標を検証した後に保存する。保存は圧縮データとmanifestを1つの値として行う。
- 不正データ・通信エラー時は前回の正常データを残す。端末保存が利用できない場合も、同梱データと実行中の更新データで動作する。
- 更新後は検索キャッシュを破棄し、表示中の検索結果・地域別一覧へ反映する。
- 地図データ、会場名の住所検索、iOSの署名・広告設定は従来どおり。

## 運用

- 通常の編集は次の日次実行で反映。急ぎの場合はGitHub Actionsの `Update sheet catalog` → `Run workflow` を実行する。
- 店舗の削除は行を消すより「確認状態」を閉店へ変更する。行削除は意図確認が必要として公開を止める。
- 住所変更と同時に座標も更新する。座標未確認なら空欄にすると地域別一覧には残る。
- シートが非公開になった場合は取得に失敗して直前データを維持する。共有権限を自動で広げない。
- Actionsに実行結果、14日保持の監査artifactを残す。古いR2版の自動削除は行わない。
- 同梱データの更新時は従来の監査・ビルド手順も維持する。
- GitHubの公開リポジトリでは、リポジトリの活動が60日間ないと定期実行が無効になる仕様がある。長期間開発を休止する場合はActionsの有効状態も確認する。詳細は[GitHubのschedule仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)を参照。
